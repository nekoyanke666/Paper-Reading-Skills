# Tree Scope, Cross-View Connections, and Stable Layout

## Explanation purpose

The main tree answers the paper's core question and uses its title. It navigates the argument rather than listing terms. Secondary trees answer focused questions about mechanisms, proofs, evaluation, prerequisites, or alternatives, starting from substantive existing nodes rather than fabricated roots.

Split when predicates proliferate, topics mix, cross-links become hard to follow, or details have an independent question. Review density/splitting above eighteen nodes. There is no fixed depth or overall knowledge cap: any node may extend into another tree.

## Sharing and scope

Define a global node once. Views hold nodeIds, linkIds, positions, and routes. A secondary tree shares at least one substantive node, not merely the same text, so its origin is visible. Shared content updates together; positions and relationships may differ.

Keep shared-count markers and sidebar links that switch and locate the same ID. Displayed edges have both endpoints in the view. All relations expands only this view's cross-links. primary means initial reading path, not stronger evidence; it must not hide refutation or critical limits to beautify a conclusion. Initial primary edges still connect all visible nodes to the reading start.

Before archiving a secondary tree, rehome unique important active nodes/edges rather than leaving invisible active material.

## Cycles

Feedback cycles are legal; do not distort a mechanism to force acyclicity. In a logical graph, distinguish dependence, equivalence, and circular argument. Drawable cycles are not valid proofs by themselves.

## Layout order

1. Preserve IDs, positions, and reader context.
2. Search deterministically around a related anchor for new space, avoiding nodes, existing routes, and labels; expand the canvas when needed.
3. Initial arrangement follows the research context. The same canonical data and layout version yield the same positions without imposing fixed columns/levels.
4. Prefer the approved curved style; use deterministic obstacle-avoiding rounded routes when necessary. Labels must not overlap or sit at ambiguous intersections.
5. Reuse routes only if endpoint signatures and display-label geometry still match.
6. Move existing nodes only with explicit layout-repair intent/reason, restricted to affected views rather than shuffling the whole map.

Unavoidable crossings may remain if lines do not pass through unrelated nodes and direction remains clear. Machine geometry does not replace expert checking of the reading logic. Localized labels require fresh geometry checks; source identities and prior node positions remain stable where feasible.
