# Paper Add Map

Create the requested new tree inside the paper's existing map, not a separate website or replacement main tree. A new tree is an explicit deliverable; it does not depend on whether an incidental teaching update would otherwise justify a tree.

## Process

### 1. Restore the paper and map

Read [paper-memory](../../interfaces/paper-memory/SKILL.md) to restore the paper, saved interaction language, settings, role, sources, glossary, canonical graph and map entry path. Preserve translation, figure and detailed-explanation progress and any interrupted return point. Read [paper-expert](../../interfaces/paper-expert/SKILL.md) for the saved perspective; announce it briefly only when a new perspective must be established.

Read [paper-map](../../interfaces/paper-map/SKILL.md) and its [new-tree workflow](../../interfaces/paper-map/references/tree-requests.md). Restore the latest managed local record as well as canonical memory before deciding changes. If more than one paper is plausible, resolve the target before writing. If no paper/map is identifiable, ask for the paper or existing map; do not fabricate a session. Repair a missing entry for an identified paper using the shared settings and entry contracts, without restarting full preparation or translation.

### 2. Define and build the new topic

Determine whether the request is a lookup catalog, a connected explanation, or needs separate focused views. Use the user's scope and available evidence to choose a concise topic title. Only ask about ambiguity that would materially change the result.

For a list of terms, use [topic catalogs](../../interfaces/paper-map/references/topic-catalogs.md): nodes may have no edges, and their sidebar definitions explain original/English names, meanings and relevant properties. For a deeper explanation, build an evidence-grounded reading path rather than manufacturing a hierarchy. Reuse genuinely identical global concepts and definitions; equal words alone do not establish identity.

Read [paper-teach](../../interfaces/paper-teach/SKILL.md) and [paper-evidence](../../interfaces/paper-evidence/SKILL.md) for understandable terminology, provenance and uncertainty. Call [paper-sources](../../interfaces/paper-sources/SKILL.md) only for missing material needed by this topic. Identify external background separately from this paper's findings. Follow paper-map's fixed appearance, relationships, detail views, lifecycle and validation contracts.

### 3. Decide integration separately

Inspect existing trees for useful, source-supported overlap even if the user names no target. Distinguish shared node identity from placing new content into an existing tree.

- If integration is explicitly requested, choose the supported related targets, or use the named targets, and apply the concrete changes without asking for the same authorization again.
- If the user requests no integration, keep existing tree memberships, relationships and placements unchanged. Do not ask again merely because overlap exists. Shared unchanged nodes may still appear in both trees with cross-tree navigation.
- If preference is unstated and integration would help, first build the independent new tree and a concrete integration proposal. Present a popup question through the host's user-input tool naming the proposed target trees and additions. Until answered, deliver the usable independent tree and keep the proposal pending; silence is not consent.
- If no useful supported integration exists, keep the new tree separate and explain that briefly. Do not manufacture a connection or ask an unnecessary question.

Keep the new tree available after integration unless removal or replacement was explicitly requested. Integration is selective addition to approved existing views, not automatic global merging or deletion.

### 4. Persist and deliver

Follow the new-tree workflow to checkpoint canonical changes, reconcile the latest managed local history without overwriting user edits, validate, and publish through the existing local service. Reuse the stable map path and checked web link. Record the request, tree IDs, provenance, integration decision or pending proposal, revisions and publication status so a later answer can resume safely without duplicate trees.

Report the new tree's title, its purpose, whether it was integrated and into which trees, or whether a specific proposal awaits an answer. Provide the same usable map link. State any incomplete source checks or publication failures precisely. This action does not mark unread paper sections or interrupted teaching as complete.
