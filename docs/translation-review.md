# English Translation and Workflow Review

All seven entry instructions, thirteen internal interfaces, focused reference documents, default UI text, relationship definitions/aliases, example content, and supporting messages are in English. The instructions govern behavior; English is not a fixed language for future paper sessions.

## Review basis

Version 1.7.0 gives detail explanations visible small-topic headings, concrete problem/stakes/source orientation before technical content, manageable chat chapters and parenthetical required/optional labels for topics mainly from supporting sources. Supplementary location is distinct from optional personal-history supplements. New paper-simple-explain gives a shorter self-contained main research story with the same motivated flow, terminology/evidence rules and independent progress, without requiring the exhaustive full-detail manuscript. Strong narrative rationale never upgrades scientific association into causation. These are written-workflow reviews, not an independently executed real-paper teaching evaluation.

Version 1.6.0 adds local sidebar Markdown and mathematical-expression rendering while keeping graph labels literal and archive v1 unchanged. The original Markdown/TeX stays in model strings; only display markup is produced. Inline/display delimiters and explicit math fences are separated from ordinary code; unsupported math retains readable source. Pinned libraries, licenses, styles and fonts are embedded for offline rendering. Existing independent-explanation, per-mention English, time-priority and saved-history rules remain intact. Runtime checks do not claim a desktop/mobile font or overflow audit.

Version 1.5.5 adds the same concise time-priority notice to all six public entries and thirteen internal interfaces. The operational rules use scoped context/source retrieval for narrow questions, reuse valid source-grounded models and complete standalone manuscripts, load only relevant interfaces, and avoid redundant preparation, checks, checkpoints or renders. Changed evidence, requested rewrites and known confusion invalidate the affected reusable work. Requested completeness, independent narrative understanding, per-mention English names and saved-history safety remain intact. This is a written workflow review, not a measured latency improvement.

Version 1.5.4 makes adjacent English names mandatory on every named occurrence of important translated concepts and technical terms in detail/figure/ask, including repeated mentions within one paragraph and emphasized terminology. Earlier labels, a glossary and aligned original text do not substitute for the inline name. The rule distinguishes unchanged English names from translated terms and retains verified source wording, acronym clarity and the selected interaction language. Written review covers repeated same-paragraph names, later answers, bold/plain terms, translated figure headings/captions, full-translation-declined sessions and non-English-source terminology without inventing an English equivalent. No live response-generation audit is claimed.

Version 1.5.3 distinguishes entering a temporary node inspection from leaving it. Entry preserves zoom while centering the target; Close, Escape or a blank click restores the captured browsing position/scale and context. Chained and shared inspections retain the first return point. Explicit tree/detail/document navigation resets stale return state; sidebar resize and obsolete animation frames cannot recenter the graph over a restored view. This state is runtime-only and archive v1 remains unchanged. The reopening workflow checks existing viewer versions before delivering an old entry. Browser-validation limits are recorded separately.

Version 1.5.2 applies expert knowledge/relationship modeling to the shared map interface. Tree structure follows the subject and evidence rather than chat order. Node descriptions directly explain their referent, relevant workings/properties and study role; prior examples, answer fragments and figure warnings do not substitute for that account. Concise labels, shared identities and useful source-grounded limitations remain. [Map content review](map-content-cases.md) distinguishes these branches; it is a written review, not an executed real-paper rebuild.

Version 1.5.1 makes the full-detail account self-contained for readers with no earlier teaching. Its core comes from the paper and expert perspective; recorded personal connections follow the relevant core topic as removable supplements. Recall states the actual concept, meaning/result and present role. Groundwork prepares later full explanation rather than replacing it. Consistency means substantially stable core coverage/depth for the same sources, scope and settings, not identical prose. The cases in [detail narrative review](detail-narrative-cases.md) include history-free, history-rich and mismatched-history conditions; they are a written review, not an executed comparative generation.

Version 1.5.0 adds paper-add-map and paper-skill-help in English. The review distinguishes a new view from integration into an existing view, and node identity reuse from content integration. Explicit integration instructions authorize the supported work; an unstated preference with a useful concrete proposal triggers a popup, while a declined integration does not trigger another prompt. Read-only help uses the saved or current conversation language without starting paper setup. Standalone explanatory trees preserve their own root/connectivity and use an explicit reason rather than a fabricated shared concept. These are written-workflow checks, not an executed end-to-end teaching or integration-dialog evaluation.

The English release was compared with the preceding Chinese draft and the accepted requirements. The review checked meaning, task scope, instruction strength, ordering, exceptions, and cross-references rather than only checking whether non-English characters remained. The original requirement groups are preserved in these principal owners:

- Reader background, essential detail, terminology, bounded analogy, transitions, and necessary recall: paper-teach.
- Sources, finding/interpretation/inference separation, uncertainty, causality, proof, generalizability, and correction propagation: paper-evidence.
- Motivation, complete research logic, source crosswalk, substantive methods, discussion, and completion coverage: paper-narrative.
- Original figure display, panels/axes/groups, controls, observations, statistics, limits, and critical supplements: paper-figures and paper-methods.
- Direct answers, mistaken premises, ambiguity, case routing, mixed/unlisted cases, and requested understanding checks: paper-answer.
- Source collection, origin/version, extraction quality, aligned translation, and truthful missing/skipped ranges: paper-sources and paper-translate.
- Whole-paper memory before segmentation, stored explanations, shared terms/claims, independent progress, and interruption recovery: paper-memory.
- Discipline-specific role selection, announcement, persistence, confirmation, and justified updates: paper-expert.
- Fixed minimal map surface, stable identities, canonical relationship semantics, cycles, arbitrary extension, shared nodes, global search, lifecycle, stable layout, and explicit quality gates: paper-map and its focused references.
- Seven public workflows with selective internal calls: the original four reading entries, concise main-story explanation, requested topic-tree creation and read-only usage help; skills/ and the plugin/installer boundaries.

## Deliberate changes requested for this release

Fixed Traditional Chinese output becomes the confirmed target/interaction language. Aligned English–Chinese translation becomes original-to-target translation. Study terminology retains its original/English form when useful alongside target-language meaning. Biological wording remains discipline-appropriate rather than imposing a biomedical role.

Startup asks the output language and whether a full-paper translation is wanted, default Yes. Independent source preparation can proceed while answers are pending. Language is never inferred from the English instructions, source, system locale, or silence. Confirmed settings are saved before substantive language-dependent output and restored across all entries. Declining full translation skips that document, not reading or local translation questions.

The map's canonical registry labels are now English while predicate IDs and meanings are preserved. Registry version 2.0.0 records the label/alias change; UI version 1.1.0 adds locale dictionaries while retaining the same CSS, node dimensions, minimal controls, sharing, sidebar, and graph interaction. Non-English content requires saved localized labels and UI rather than changing canonical semantic IDs. Existing actual paper sessions must be migrated explicitly, not silently reinterpreted.

## Limits of the checks

Automated tests validate persistence, defaults/decline behavior, stale-state rejection, graph semantics/geometry, localization structure, installer boundaries, and reproduction. The synthetic non-English locale fixture verifies routing/completeness, not a real Spanish translation. The English instruction review is a semantic review of this release, not a claim of infallible wording or an independent agent evaluation.

No real-paper teaching evaluation has been performed. Version 1.1.0 browser checks use fictional fixtures; their exact viewport and interaction coverage is recorded separately in docs/browser-qa.md. Minimal-DOM runtime tests are reported as runtime tests. See [validation instructions](../README.md#validate) and [machine results](validation.json).

## Version 1.0.1 workflow refinement

Preparation now creates or restores the map entry by default and delivers its first usable link without waiting for the full translation. All four entries explicitly review updates on every invocation; mutation remains conditional on meaningful content. The shared delivery contract specifies stable paths, provisional minimal content, same-entry updates, and first delivery in each conversation. This changes timing and delivery policy without changing the map template, relationship meanings, or number of public entries.

## Version 1.1.0 reusable map contract

Four semantic shape roles, substantive object/concept modeling, pure cubic/straight edges, direct dragging, browser-local saved placements, view-scoped defaults, and responsive feedback are integrated into paper-map and its conditional references. The four public entry routes and saved-language workflow are unchanged. New UI labels require complete selected-language translations during migration; scientific predicate IDs and meanings remain unchanged. The viewer sources are maintained separately and compiled into the locked reusable template.

## Version 1.1.1 full-paper narrative correction

Full detail explanation now produces a complete connected manuscript before chapter delivery, covering the actual paper from research context and motivation through methods/calculations, all substantive results, and final interpretation. Short conceptual steps no longer imply separate response boundaries. New whole-paper requests begin at the narrative opening; explicit continuation restores the current run. Memory distinguishes manuscript coverage, chapters delivered, and reader-reported understanding while retaining earlier runs. Contextual recall and worked technical reasoning are integrated into the existing teaching/method interfaces. Four public entries, the saved-language setup, segmented preference, evidence rules, and map interface remain intact. See detail-narrative-cases.md for the scope and limitations of semantic review.

## Version 1.2.0 terminology and conceptual coverage

Figure/detail/question work explains required vocabulary at use and retains reusable definitions, study roles, contextual properties, and sources in the shared glossary. Domain-specific topic catalogs may be rootless and unconnected or sparsely linked, with existing node identities shared across views. This is a purpose-specific exception to narrative connectivity, not a relaxation of evidence or identity requirements. Catalog titles are topics rather than forced questions; categories are inferred from actual content instead of hardcoded to biology.

Main maps now require a source-to-map concept crosswalk and visible anchors for important questions, contributions, methods, results, and limits. One-to-many/many-to-one branches are supported with independently meaningful canonical relations. The eighteen-node threshold remains a review trigger, not a cap. The viewer adds glossary-field search, selected property display with deduplicated scoped sources, and paper-specific relationship hover text; UI version 1.3.0 records these changes. Two new UI labels require complete selected-language translations. Four public entries, the canonical relationship registry, and saved reading preferences remain unchanged. Tests and fictional-browser checks do not establish complete coverage of an existing real paper; that requires a new source-based review when its map is updated.

## Version 1.3.0 diagram files, detail trees and camera

English instructions consistently distinguish permanent portable diagram history from supplementary browser recovery and from authoritative research memory. Prev/Next traverse saved versions; editing an older checkpoint retains former future versions. Save serializes every detail tree, not just visible nodes. Low/Medium/High are independent curated memberships/relationships reusing identical global scientific records; no automatic path collapse or required nested subsets remain. The viewer keeps the same full selector and import controls even for one tree. Higher detail makes necessary concepts, methodological steps, assumptions, evaluation and limits explicit while preserving concise node labels and rich definitions.

Canvas pan/zoom is temporary navigation, separate from node coordinate editing and history navigation. In that release Center fitted the current tree; v1.3.1 supersedes automatic scaling with translation-only centering. Signed world coordinates permit expansion in all directions. Controls, status and help strings must be translated into the saved interaction language before non-English rendering; UI language during foreign archive import remains the receiving viewer's, while source content and provenance remain intact. Four public entries and all source-grounded teaching, language/setup, terminology and whole-paper-memory rules are preserved.

## Version 1.3.1 selection direction

Incoming and outgoing are relative to the currently selected node, not biological stimulation/inhibition or proof strength. Self refers only to an actual permitted self-edge; reciprocal connections between distinct nodes remain two separate edges. Undirected edges retain no arrow. Hypothesis dashes and inhibitory T endpoints are preserved under focus colors. Localized group headings, explicit source/target names and accessible relationship labels supplement color. All five new UI keys require saved-language translations before rendering. The portable archive schema stays v1; focus is temporary and creates no graph or history changes. Four public entries and the existing whole-paper teaching rules remain intact.

Version 1.3.1 also makes zoom exclusively user-controlled. Selection, navigation, viewport/sidebar resizing, imports and saved-version changes preserve scale; Center translates without fitting. Nodes and labels are laid out at their real display size and SVG geometry redraws natively, avoiding a permanently CSS-scaled bitmap board. Device-pixel display snapping leaves canonical world positions unchanged.

## Version 1.4.0 workspace-scoped managed storage

Ordinary Save now means writing to the generated entry's history/ directory, not choosing a browser file handle or exporting a download. Only Back up elsewhere chooses an external destination, and it does not mark unsaved managed edits as saved. A local helper supplies disk-backed restoration, conflicts and imports while static previews remain explicitly read-only for Save. New local-storage/interface messages require the saved language. Per-paper folders are allocated relative to each active workspace and reused by the same paper across chats; users, drives, workspaces and ports are never hardcoded. Copying the complete entry folder preserves the archive and relative pointer. Archive v1, four public entries, user-only zoom and all research/teaching rules remain intact.

## Version 1.4.1 map opening

Opening/reopening an existing map is a navigation request. The agent resolves the saved per-paper folder, checks or recovers its service, submits the live URL to the host browser panel when supported, and supplies a clickable web link. A queued panel is reported as queued. Manual .cmd execution is an optional outside-app fallback, not the default Codex workflow. Opening alone does not restart language/translation setup, expert selection, reading or map construction. The four public entries, English instructions, selected-language behavior, archive v1, storage scope, renderer and saved scientific records remain unchanged.
