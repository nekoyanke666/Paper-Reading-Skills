# Expert Map and Node Explanation Review

Version 1.5.2 addresses a graph organized like prior chat and node details that rely on earlier examples, extracted answer fragments or figure-policing warnings. These cases are a written contract review, not an executed real-paper map rebuild or an independent agent evaluation.

## Cases and observable criteria

1. **Expert structure rather than transcript.** Given a primary paper and the relevant expert profile, select its substantive objects, conceptual distinctions, mechanisms/methods, measurements, evidence and findings. Build relationships from their actual meanings. Earlier questions reveal gaps but do not automatically become nodes or define branch order. Different chat histories do not justify different scientific relationships for the same source-defined objects.
2. **Term reached through search.** The reader opens a catalog-only term without any prior chat. The sidebar defines the actual referent, explains its relevant properties/process and role in this study, provides necessary local terminology and traceable source basis. A link to another node or an instruction to remember a prior example cannot supply the missing explanation.
3. **Method with a meaningful scope.** The node denotes a reported procedure. Explain its actual purpose, inputs, substantive operations, outputs and interpretation, with necessary assumptions or notation. An example invocation or one familiar analogy fails as its primary account. Unreported steps remain identified as unreported rather than invented to appear complete.
4. **A figure locator is evidence.** The node denotes a finding. State the research objects, actual comparison/measurement, observed result and supported interpretation. A figure number can locate the basis. A statement about what the depicted object should not be mistaken for fails when it replaces the actual finding or concept.
5. **Examples are not definitions.** Removing references to an older example or an optional worked illustration still leaves the substantive definition and workings. The default sidebar directly explains the actual study. An optional requested calculation follows the complete account and distinguishes invented values from reported data.
6. **Useful limitations remain.** Explain the object/method/result first, then state a specific condition or inference boundary with its reason. This remains valid scientific scope. A freestanding warning about an unexplained figure is not an acceptable substitute for either the explanation or a concrete limitation.
7. **Fuller text, same identity.** An inadequate description is repaired without inventing a new referent, moving the existing node or adding a generic relation merely to show activity. Reconcile saved user edits and keep shared definitions consistent across tree/detail memberships. A reusable-skill update alone does not rewrite existing paper records.
8. **Catalog or focused view chosen for purpose.** A lookup catalog can have zero edges while each node is fully explained. A mechanism or algorithm view uses supported semantic connections. Neither extra arrows nor a forced hierarchy establishes expert understanding. Retain main research coverage, honest scope and the locked appearance.

## Review scope

The contracts were reviewed for consistency with these cases. Expert organization is owned by [the content model](../interfaces/paper-map/references/content-model.md); local explanation quality by [the node explanation contract](../interfaces/paper-map/references/node-explanations.md); source interpretation and persistence retain their existing owners. Structural validators check packaging and reference integrity, not whether a generated explanation is pedagogically complete. No live generation comparison, private-paper rewrite or new browser audit is claimed.
