# Version 1.5.0

Two requested public skills extend the original four reading workflows:

- paper-add-map creates a new topic tree in the current paper's existing map, including rootless term catalogs with no edges and connected explanatory views. It separates shared node identity from integration into existing views. Explicit integration runs directly; a declined integration leaves old view content unchanged; an unstated preference with useful overlap produces a concrete popup proposal while the independent new tree remains usable.
- paper-skill-help lists all six public skills with examples, explicitly including integrated and independent tree requests. Help works without a paper and does not start setup or execute its examples.

The installer exposes six public entries and retains thirteen path-loaded internal interfaces. Existing owned four-entry installations can be upgraded without touching unrelated skills. New tree requests preserve paper settings, source provenance, interrupted reading, pending proposals and the stable map link.

Secondary narrative views with no genuine shared narrative anchor can explicitly record standalone=true and a nonempty standaloneReason. Internal root/connectivity and evidence checks still apply. Catalogs continue to support sparse or zero edges. This is additive metadata; appearance, relationship registry and portable archive v1 remain unchanged.

The shared workflow requires restoring and reconciling the latest managed file before publishing additions, preserving user edits and previous Save versions. This release adds instructions, not an automatic cross-model merge engine.

## Validation scope

See [machine results](validation.json). Tests check independent/selected-view additions, existing node identities and positions, standalone validation, session interruption and pending-proposal persistence, six-entry installation/upgrade safety and archive checkpoint preservation. The existing JavaScript runtime and real local HTTP/filesystem suites are retained. New popup decisions and an end-to-end real-paper tree integration have not been executed; browser appearance was not changed or re-audited in this release.
